# Roadmap

The detailed six-month delivery sequence is in [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md). Protocol decisions are reviewed through [RFCs](rfcs/README.md).

The roadmap is evidence-gated. Dates are directional; a capability moves to “supported” only when its claim has a reproducible test or benchmark.

## v0.1 — Local evidence engine

- [x] Deterministic CPU fingerprint extraction.
- [x] Durable SQLite catalog.
- [x] Temporal-offset evidence.
- [x] CLI, authenticated API, and local console.
- [x] Synthetic end-to-end and restart tests.
- [ ] Public, redistributable transformation benchmark.
- [ ] Calibrated match and abstention thresholds.
- [ ] Signed release artifacts and software bill of materials.

## v0.2 — Provenance workflow

- Evidence, provenance, and policy schemas with cross-language golden vectors.
- Resource-bounded Rust fingerprint kernel and initial Python binding.
- Dataset Guard job API and immutable result manifests.
- C2PA manifest validation and external soft-binding lookup experiment.
- Dataset scan command with JSONL and Croissant-style reports.
- Croissant metadata import/export experiment.
- Generated TypeScript and Python API clients.
- API-key rotation, scoped identities, and an append-only audit trail.
- Postgres adapter and measured catalog/query scaling envelope.

## v0.3 — Interoperability and scale

- WASM extraction after Rust/Python byte-for-byte compatibility is proven.
- MCP adapter for agent-controlled pre-publication checks.
- Background jobs for large private dataset audits.
- Optional learned similarity reranker with separate evidence labels and benchmark.

## Explicit non-goals

- Declaring whether content is copyrighted or legally infringing.
- Claiming universal music coverage without catalog partnerships.
- Detecting whether arbitrary media was generated by AI.
- Shipping Kubernetes, streaming, or multi-region architecture before measurements justify it.
