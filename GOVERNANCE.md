# Governance

Auxris begins as a maintainer-led open-source project. The purpose of governance is to make technical authority visible while the contributor community develops.

## Roles

- **Contributors** submit issues, documentation, fixtures, tests, or code under the DCO.
- **Reviewers** are recurring contributors trusted to review a defined subsystem.
- **Maintainers** own releases, security response, compatibility decisions, and repository administration.

The founding maintainer is the GitHub repository owner. Additional maintainers are nominated publicly after sustained contribution, sound review judgment, and agreement with the project's evidence-first principles. Existing maintainers approve additions by lazy consensus.

## Decisions

Routine changes use pull-request review. Material decisions—public API compatibility, algorithm versions, governance, licensing, collection of shared catalog data, and external standards participation—start as a public proposal and remain open for at least seven days when no security embargo applies.

Maintainers seek consensus. When consensus is not possible, the repository owner records the decision and rationale publicly. Conflicts of interest must be disclosed.

## Releases and security

Maintainers publish release notes, dependency locks, known limitations, and benchmark provenance. Security reports remain private until coordinated disclosure. No maintainer may privately relicense community contributions without the permissions required by the Apache-2.0 license and their contributors.

This model will be revisited after the project has at least three regular independent contributors or a hosted service materially funds development.
